# A PM operating system in Claude Code

How I ran product work on an early-stage AI product at a research and development lab in 2026, with Claude Code as the operating layer: status files as the single source of truth, scoped instances for parallel tracks, skills for the recurring rituals, and integrations with the tools the organization already used. Names, internal project names and workspace details are removed.

## The split

The system separates information management from judgment. Claude Code kept the status files, the meeting context, the formatted drafts and the coordination between tracks. I kept the decisions, the relationships, the meetings and the calls. The rule was that skills draft and I approve. When either side does the other's job, the system breaks.

## The documents

1. [Playbook](01-playbook.md): the guide I put together in March 2026 for colleagues who wanted to run a project the same way. The status-file system, the instruction hierarchy, scoped instances and how they hand off, document ownership, integrations, skills, a red-team step before big decisions, pre-committed decision criteria, and what didn't work.
2. [Weekly rhythm](02-weekly-rhythm.md): the weekly plan for the pilot, with product work first and project work timeboxed around it.

At a staff onsite in February 2026 I demoed the system to the operations team, who asked for my status files to see what could be replicated. I still run my work on a version of the same pattern.

The product's own experiment loop is in a separate repo: [weekly-experiment-loop](https://github.com/amijach1103/weekly-experiment-loop).
